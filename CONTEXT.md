## Факты, которые расходятся с исходной постановкой
1. **CRLF в репозитории нет.** `git ls-files --eol` — все текстовые файлы `i/lf`. CRLF был только в локальной
   Windows-копии (autocrlf). `.gitattributes` всё равно нужен, но коммит нормализации будет пустым.
2. **Фото не загружаются на сервер.** Фото перекодируется через canvas (EXIF и GPS из файла при этом теряются),
   хранится только в localStorage устройства; в таблице `reports` колонки для фото нет. Публичных загрузок фото сейчас нет.
3. **Реальные персональные данные в открытом доступе — это координаты и anon_id:**
   - `reports.lat/lon` — точная точка GPS, читается всеми;
   - `event_checkins.lat/lon` — точное положение человека в момент check-in, читается всеми;
   - `anon_id` читается всеми → можно связать все сообщения одного устройства и выдать себя за него.
4. **Дыра в RSVP:** политика `delete ... using (true)` на `event_rsvps` позволяет любому анониму удалить
   ВСЕ записи на любое мероприятие одним запросом.
5. Лимит частоты считается по `anon_id`, который присылает клиент → обходится сменой id.
6. `PLAN.md` (в публичном репозитории) называет организацию и рецензента по имени — это публичное упоминание без согласия.
   Из истории git это не убрать без переписывания истории (запрещено) — нужно решение владельца.
7. Песочница не имеет сети до supabase.co, vercel.app, aetherisearth.live, open-meteo.com.
   `npm run test:security`, проверка превью и продакшена отсюда невозможны → проверка через GitHub Actions
   (у раннеров сеть есть) или после расширения сетевого доступа песочницы.
8. Защиту ветки `main` токен этой сессии выставить не может (403) — это делает владелец в настройках GitHub.

## Ограничения
- Необратимые операции (merge в main, миграции в боевой Supabase, включение публичной записи, удаление данных) — только после явного «да».
- Без force-push и переписывания истории. Коммиты небольшие, по темам, только при зелёных тестах, `git add` по списку.
- Секреты только через env; `.env*` в .gitignore, `.env.example` без значений.
- Не выдумывать данные, источники, цитаты, юридические формулировки (черновик с пометкой «на юридической вычитке»).
- Казахский текст — в `docs/kk-review.md` для носителя, в интерфейсе не помечать.
- Слова «проверено/подтверждено/решено» в статусах запрещены (tests/reports.test.ts).

## Решения (пока предложения, ждут «ок»)
- Заголовки безопасности — `vercel.json`. CSP с `'unsafe-inline'` в script-src (статический export не даёт nonce;
  Next вставляет inline-скрипты гидратации) — компромисс записан явно.
- Приватность в БД: новая миграция №7 — `anon_id` и точные координаты убраны из публичного чтения (column grants),
  наружу — округлённые координаты и `sha256(anon_id)` для «это моё»; RSVP отменяется только через функцию с проверкой anon_id;
  координаты check-in не читаются публично.
- Фото — по решению владельца (см. вопросы в чате).
- /ru/community и /kk/community — сделать страницы (строки в словарь), а не убирать ссылки.
- Проверка превью/продакшена — workflow на `deployment_status` в GitHub Actions.
