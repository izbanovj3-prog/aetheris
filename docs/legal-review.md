# Вопросы для юридической вычитки

Черновики: `lib/legal.ts` → страницы `/privacy`, `/terms` (и `/ru/…`, `/kk/…`).
Тексты написаны командой разработки и описывают то, что делает код. Юридических
формулировок «за юристов» в них нет: там, где нужно решение, текст прямо
говорит, что вопрос не решён. Ниже — что именно нужно решить. После вычитки
убрать плашку «черновик» (`draftBanner`) и пометки «(черновик)» в подвале.

## Что собирается (по коду, на 03.11.2026)

| Данные | Где | Публично | Срок |
| --- | --- | --- | --- |
| Категория, серьёзность, заголовок, текст, город, время | Supabase `reports` | да | не определён |
| Координаты, округлённые до 0,01° (~1 км) | Supabase `reports` | да | не определён |
| Случайный идентификатор устройства | Supabase `reports`, `events`, `event_rsvps`, `event_checkins` | нет | не определён |
| Расстояние до события при отметке (без координат) | Supabase `event_checkins` | только число отметок | не определён |
| Название, описание, место и точка события | Supabase `events` | да | не определён |
| Хэш IP с суточной солью | Supabase `private.network_hits` | нет | 24 часа |
| Фото | только браузер пользователя (localStorage) | нет | до удаления пользователем |
| Аналитика посещений и скорости | Vercel Web Analytics / Speed Insights | нет | по правилам Vercel |

## Вопросы

1. **Оператор персональных данных.** Кто юридически ведёт проект (физлицо,
   учебное заведение, организация)? Сейчас в тексте: «независимый
   студенческий проект», контакт `izbanovj3@gmail.com`.
2. **Являются ли эти данные персональными** по Закону РК «О персональных
   данных и их защите» (идентификатор устройства, координаты ~1 км,
   свободный текст, хэш IP)?
3. **Локализация.** Проверить требование закона о хранении персональных
   данных на территории РК: база Supabase и хостинг Vercel находятся за
   рубежом (регион проекта Supabase нужно уточнить в настройках).
4. **Форма согласия.** Достаточно ли галочки «Я понимаю, что сообщение
   будет публичным» перед отправкой (`components/community/ReportFlow.tsx`)?
   Нужна ли отдельная формулировка согласия на передачу в акимат/инспекцию?
5. **Возраст.** Нужны ли ограничения или отдельный порядок для
   несовершеннолетних?
6. **Срок хранения** сообщений и событий — сейчас «пока не удалят».
7. **Права на тексты сообщений** (лицензия на публикацию и передачу).
8. **Передача сообщений органам** (статус ④): основание и порядок.
9. **Vercel Web Analytics / Speed Insights**: нужен ли баннер согласия.
10. **Ограничение ответственности и применимое право** в условиях использования.
11. **Удаление по запросу**: срок ответа на запрос, как подтверждать, что
    запрос от автора сообщения (аккаунтов нет).
12. **Журналы платформ.** Vercel и Supabase сами ведут журналы запросов с
    IP-адресами. Политика говорит, что сам адрес «не хранится» — это верно
    для базы Aetheris, но не для журналов хостинга. Нужно ли это упомянуть
    и каков их срок хранения?
13. **Окно между выкладкой и миграцией 7.** Пока миграция 7 не применена,
    идентификаторы устройств видны всем, а отметки на событиях по старому
    пути хранят точную точку. Допустимо ли такое окно или миграцию нужно
    применять сразу (см. `supabase/README.md`)?
14. **Кнопка «Удалить».** Сообщения, отправленные до текущей версии сайта
    или в окне из п. 13, удалить с устройства нельзя — только через
    команду. Текст политики обещает кнопку для «каждого сообщения с этого
    устройства».
